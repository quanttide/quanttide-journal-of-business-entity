# 2026-08-26 实训基地群指导（量潮课堂）

实训基地群今日主要议题与指导要点。

## 技术选型：RAG vs LLM 知识库

- 纯 RAG 在缺乏数据结构认知的情况下做不出高质量知识库应用；上下文窗口变长后，"LLM 知识库"方案更优：资料统一放仓库管理，人机与不同 Agent 围绕同一仓库协作，维护成本低。
- 第二大脑有自定的结构，帮助团队任何人理解领域结构，维护全局应用负担小——成员因此能在数周内开始主导多个产品（结构同构，只需理解业务细节）。
- 技术负责人观点：核心在怎么构建索引——方法是纯白盒化（把脑内索引方式显性化构建）。
- 判断：RAG 迟早需要，但不要全局黑箱，要白盒 RAG；当前知识库仍反复变动、缺验证，尚不足以做 RAG；但规模已到人脑维护不下去、白盒结构快失效的节点——需要引入白盒化 RAG。

## 第二轮提交点评

- 较第一轮明显进步：第一轮像 AI 生成的大清单，第二轮可见人类裁剪与思考——培养方案在起作用。
- 仍缺两点：产品原型（到底长什么样）、用户视角（用户旅程/故事地图等规范方法，从用户角度描述收益）。AI 易生成似是而非的功能与页面，人类使用时"没有呼吸感"——产品设计以"讲故事"手段让人类理解是关键步骤。

## 课题申请点评（三个题目通病）

- 申请者认识到侧面、切入点问题不大，但对真实需求理解不充分。
- 需求大小取决于如何解释——同样的需求，解释得好是大需求，否则是小需求；甲方难以愿意为小需求投入资源。
- 商务侧最大诉求：前期客户沟通摩擦大、谈判规模化难（高度依赖有经验商务）；知识管理侧诉求：把现有结构显性化记录（流沙→固定），在此基础上再搜索。

## 甲方思维训练（核心）

- 当前课题申请水平约等于学年论文——企业更希望看到"为什么这东西能帮我们赚钱"。
- 建议产品与技术找商务经理搭档，由商务帮助搞定甲方；企业服务市场必须包装需求，需要商务与销售配合。
- 捕捉真实需求是最稀缺的能力——"最贵的东西永远都是真实的需求"；不调研甲方而凭市场常识猜测，做出的东西大概率是已试过且不好用的。

## 机制说明

- 群聊沟通是训练的一部分：不提问、不沟通就过不了——建群目的就是给候选人直接沟通窗口。
- 机制设计初衷：企业服务市场需要什么，就设置对应训练机制；同时服务学生与招聘。
- 机制可改进方向：融合课堂与招聘、提供更好服务、从用户自身出发。

## 工作方法提炼（从群聊指导中）

### 工作流程（实训基地训练线）

```
投递 → 准入问卷 → 加入实训群 → 选题（自主发现真实问题）
  → 课题申请（提交）→ 逐轮点评（否定/指导）→ 迭代提交
  → 验收标准：实际产出（真实创造的东西，不是固定答卷）
```

### 工作方法

1. **验证先行，先试再判断**：直觉来自试过（RAG 刚能用就试 → 形成"纯 RAG 不行"的直觉 → 追踪方案演化 → 判断时机）——方向来自验证
2. **白盒优先，结构显性化**：脑内索引方式显性化构建（白盒 RAG，不要全局黑箱）——结构让团队任何人能维护
3. **甲方思维，真实需求 > 猜测**：一切从"为什么能帮我们赚钱"出发；捕捉真实需求是最稀缺能力——凭常识猜做出来的都是试过且不好用的
4. **沟通即训练**：群聊是训练机制的一部分——不提问不沟通就过不了；点评（否定+原因）是训练环节
5. **协同搭档**：产品/技术 + 商务经理搭档——商务帮助搞定甲方（企业服务必须包装需求）
6. **机制服务业务**：企业服务市场需要什么，就设对应训练机制——机制 = 业务需求的映射
7. **机制自改进**：机制本身也在被训练（融合课堂/招聘、从用户出发）——机制与受训者共同迭代

### 本质主线

用真实业务场景做训练场、以实际产出做筛选器、用沟通做反馈环——"以实际成果为核心"选拔标准的完整落地。
