# 2026-08-31 数据工程师候选人的「流程状态数据」课题

来源：量潮实训基地飞书群（自 qtclass/2026-08-31 提炼）

一位应聘数据工程师的候选人提出课题方向：**先把流程状态沉淀成结构化数据，再让上层从底座读，而不是从邮件原文猜。**

背景：此前的讨论提到「邮箱自动化的主要难点在于读海量上下文、猜不出实际状态」——候选人的理解：邮件智能体不是不能做，是缺结构化数据。

计划交付：

- 流程节点的结构化配置（机器可读，未来平台直接对接）
- 从邮件/群聊抽取「共识状态」，沉淀为状态库
- 交付清单校验器 + 中后期失控预警
- 兼容过渡期（邮件）和未来（平台 API）多种数据源

明确不做运行时/智能体层（留给更擅长 Coze/低代码的同学），提出搭伴：「我做底座，你做上层，互不重叠」。

公司回复：邮件工作流文档链接（handbook 的 qtdata/connect/email.md）；流程状态数据目前可开放「邮件导出」「群聊脱敏」「脱敏文档」，不涉及公司机密的信息提供最大程度帮助，内部 API 暂未开放。

后续：该课题 9-02 进入交付阶段，申请真实数据验证（覆盖 E1~E18 完整项目周期的样本项目、邮件导出、已脱敏）。
